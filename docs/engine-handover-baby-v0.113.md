## 4. 進化先の欄の取り出し方

- 欄の形: ベイビィの記録の `pokemon.evolves_to`（日本語名の配列、印刷の順）。欄がない（ベイビィ以外）は適用外、`null` は未確認、`[]` は形式の上の「印刷に進化先がないと明示」（今は該当なし。kyuura の検査が拒否する）。[データの構造](data-schema.md#進化先pokemonevolves_to)。
- エンジンの `scripts/extract_kyuura_cards.py` は `pokemon` を丸ごと写す（`FIELDS`）ので、写しの元（`KYUURA_COMMIT`）を上げると、写しのベイビィの記録に `evolves_to` が入る。ただし `FIELDS_USED_BY_ENGINE` にこの欄はなく、`kyuura_engine/cards.py` もベイビィを「（ベイビィなど）は未実装」として拒否している。ベイビィを実装するときは、`FIELDS_USED_BY_ENGINE` に `pokemon.evolves_to` を加え、カードの定義に進化先の名前の並びを持たせる必要がある。
- 写しの元を上げるときに見直すこと: 写しの検査（`--check`）とデータの移行の連鎖（`PREVIOUS_KYUURA_COMMIT`・`V0_69_KYUURA_COMMIT` など）、採用の記録（`card_sources.json`）の `kyuura_commit`、研究の対応表（`research_links.json`）の研究の基準、固定値を持つテスト（写しの件数・欄・`data_gaps`）。kyuura の側の変更は 3 章のとおりで、既存の登録の値は変わらない。
- `null`（未確認）の記録を受け取ったら、進化先を推測せずに止めること（今の 13 枚はどれも値がある）。進化先の組み合わせは名前だけで決まり（公式ルール p.324「書かれていない組み合わせでカードを重ねてはいけません」）、`evolves_to` の順番は印刷の順で、処理の意味はない。

## 5. ルールの根拠（基準版で使えるもの・まだ決まらないもの）

基準は公式ルール 2000.02.14 版（P43）。『トレーナーズ』Vol.5（P38。2000-03-01）は後の資料で、2000.02.14 版の根拠にしていない（P38 の順番・説明を P43 の規定として扱わない）。記録は `data/sidecar/rulings.json`（[カードの裁定と公式の最新の説明](rules/card-rulings.md)）。

- 基準版で使える一般の条項: GR-2000-P308-BABY-SETUP（デッキ・切り直し・対戦準備）、GR-2000-P309-BABY-BENCH（手札からベンチ。直接バトル場は不可）、GR-2000-P314-BABY-RULE（ルール）、GR-2000-P310-BABY-EVOLUTION（ベイビィの上にたねを重ねるのも進化。組み合わせは印刷の名前だけ。番の制限・受け継ぐもの・回復するものは進化の項のとおり）、GR-2000-P315-EVOLVED-BABY（ベイビィから進化したたねは場で「進化ポケモン」）、GR-2000-P313-POKEMON-COMPOSITION（場をはなれたらカードにもどる）、GR-2000-P323-ATTACK-FAILURE（失敗してもワザを使ったことになる）、GR-2000-P325-PRE-NEO-BABY（ネオより前のカードの説明の読み方）。
- 裁定: CR-BABY-RULE-COIN（CONFIRMED。ベイビィの相手がワザを使うたびに投げ、「うら」なら失敗して番が終わる）、CR-BABY-RULE-COIN-STEP（SUPPORTED。宣言のあと・説明の処理の前。「うら」なら説明を処理しない）、CR-BABY-RULE-NOT-POWER（SUPPORTED）、CR-BABY-WITHOUT-ATTACKS（SUPPORTED）、CR-NEUTRAL-SHIELD-EVOLVED-BABY・CR-DEVOLUTION-SPRAY-EVOLVED-BABY（CONFIRMED。一般の定義の個別の当てはめ）。
- まだ決まらない問い: UQ-ATTACK-PRE-DAMAGE-COIN-ORDER（ベイビィのコインと、すなかけなど・こんらん・スタジアムのコインの順番、「うら」のあとのこんらんのコイン）、UQ-NEO-TEXT-BABY-CATEGORIES（neo の説明の「たねポケモン」「進化カード」にベイビィ・ベイビィの上のたねをふくむか）。ほかに、ネオより前の「…トラッシュしないと使えない」の説明とベイビィのコインの前後は決めていない（CR-BABY-RULE-COIN-STEP の notes）。
- 確かめ方: p.308・p.314 のルール・p.325 の「たね」は kyuura の 2026-10-12 の画像の読み取り。そのほかの多くは既存の転記（`existing_transcription`。`data/Silver_Bible_structured.md`）で、kyuura は原典の画像で確かめていない。新しく原典で確かめたい箇所: P43 p.309・p.310・p.313・p.314・p.315・p.323「12」・p.324「18」・p.325「24」と、P38 pp.58〜62（ベイビィポケモン Q1〜Q6・p.60 の文の範囲）。

## 6. 実装のときの注意（kyuura の裁定ではない）

- ベイビィの防御（ルール）は特殊能力ではない（CR-BABY-RULE-NOT-POWER。SUPPORTED）。特殊能力の登録表・特殊能力を止める効果（モクモク・かがくへんかガスなど）の仕組みで扱うと、止まらないはずのルールが止まる。
- ワザのないエレキッド・ププリン: ルール上は使える（CR-BABY-WITHOUT-ATTACKS）。バトル場にいるあいだはワザを使わずに番を終える。今のエンジンの拒否（ベイビィの段階を未対応とする分類）は、エンジンの実装の範囲で、ルール上の禁止ではない。
- 印刷の段階と場の状態を分ける: カードの `stage` は印刷の段階（ベイビィは `baby`、進化先は `basic`）のまま。ベイビィの上に重ねたたねは、場にいるあいだ「進化ポケモン」・進化カードとしてあつかい（p.315・p.325）、場をはなれたらたねポケモンカードにもどる（p.313）。エンジンの重なりの前提（いちばん下がたねポケモン・`EVOLUTION_STAGES`・ログ `evolve` との対応・1 進化した番。エンジンの CLAUDE.md が見直しを求める箇所）は、ベイビィ → たね → 1 進化 → 2 進化の重なりに合わせて見直す必要がある（転記の p.313 は、進化カードの下にベイビィポケモンカード・たねポケモンカード・進化カードがある重なりを書く）。
- 「その番の最初から場にいたポケモン」・おたがいの最初の番は進化できない、などの進化の制限は、ベイビィの進化にもそのまま当てはまる（GR-2000-P310-BABY-EVOLUTION が p.310 の項を参照する）。
- ネオより前のカードの説明の「たねポケモン」はベイビィもふくむ（p.325）が、neo の説明には一律に当てはめない（UQ-NEO-TEXT-BABY-CATEGORIES）。
