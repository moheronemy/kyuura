# 利用者が指定したプロモ 3 枚の簡略化（エンジン固有の扱い。2026-10-31 の記録）

kyuura-engine で、プロモカード 3 枚（2 種類）の条件を省いて処理するという、**利用者の指定**の記録です。原典の調査・公式の裁定・エラッタ・最新の説明ではありません。kyuura のカードデータ（印刷の文面の転記）は変えていません。

## 1. 位置づけ

- 利用者は、これらがプロモカードで、ハマちゃんのヤドキングはジョークカードの性格が強いことから、**詳細な追加調査は不要**と判断しました。この指定にしたがい、この記録のためにカードの画像・ガイドブック・Q&A を新しく確かめていません。
- 利用者の指定（原文のまま）:

  > のピカチュウについては誕生日の確認をせずに通常のコイントスのみとし、ハマちゃんのヤドキングに関しては発話要件を無視して実装します。

- 分類: エンジン固有の**簡略化**（kyuura の sidecar の `engine_positions` でいう `kind: simplification` に当たる性質のもの）。公式の裁定（CR-… の CONFIRMED・SUPPORTED）・最新の説明（LD-…）・エラッタ・転記の訂正・画像の照合として登録していません。
- 日付: 2026-10-31 は kyuura にこの指定を記録した日です。カードの発売日・原典の公表日ではありません。指定の日時・URL は記録していません（利用者の依頼の中の指定で、別の公開資料はない）。

## 2. 対象と指定された扱い

kyuura の文面は `data/cards.json`（基点 `57d01f4` の値。この作業で変えていない）からそのまま引用しました。

| カード id | 名前（kyuura の値） | 対象 | 印刷の文面（kyuura の転記） | 省く条件 | エンジンで指定された扱い |
|---|---|---|---|---|---|
| `PR1-044`・`PR1-090`（同じカードの組 `SC-PR1-044`） | _のピカチュウ | attack0「おたんじょうび」（雷雷・30+） | 今日がこのカードの持ち主の誕生日ならコインを投げ、「おもて」なら、50ダメージを追加する。 | 「今日がこのカードの持ち主の誕生日なら」 | 誕生日・日付・人物を確かめず、使うたびにコインを 1 回投げる。「おもて」なら基本のダメージ 80（30+50）、「うら」なら基本のダメージ 30 |
| `PR1-072` | ハマちゃんのヤドキング | attack0「こまったなあ」（超） | 「こまったなぁ」と3回つぶやかないとこのワザは使えない。自分と相手は「こんらん」状態になる。 | 「「こまったなぁ」と3回つぶやかないとこのワザは使えない。」 | 発話の要件なし。必要なエネルギーを満たせば使え、自分と相手の対戦ポケモンを「こんらん」にする |
| `PR1-072` | ハマちゃんのヤドキング | attack1「どつく」（無無・20） | 「ええのかなあ」と3回つぶやかないとこのワザは使えない。 | 文面のすべて（発話の要件） | 発話の要件なし。必要なエネルギーを満たせば使え、20 ダメージ |

- 「基本のダメージ」は、ワザの数字としてのダメージです。弱点・抵抗力・プラスパワーなどの計算は、ほかのワザと同じく通常の規定によります（この指定で変えない）。
- 「自分と相手」を「自分と相手の対戦ポケモン」と書いたのは、利用者の指定の言い方です。この記録で新しく原典から決めたことではありません。

## 3. 省くもの・残すもの

**省くのは誕生日の条件と発話の条件だけです。** 次はこの指定で変わらず、通常の規定のとおりです。

- 必要なエネルギー、ワザを使える番・段階、ねむり・マヒでワザを使えないこと、こんらんのコイン（ワザを使うときの p.309 の手順）、ESP などのダメージを変える効果、弱点・抵抗力、ダメージを受けない効果などの無効化、進化・きぜつ・サイド。
- ワザの処理の細かい順番（たとえば「こまったなあ」で自分と相手のどちらを先にこんらんにするか、自分がすでにこんらんのときにどうなるか、相手が「ダメージを受けない」状態のときに効果の要素がどうなるか）・その場面に到達するかの問いは、**この指定で決まったものとしません**。必要ならエンジンの側で、既存の規定・論点と照らして扱います（原典で決められなければ止める）。

誕生日の扱い:

- 誕生日を「いつも真」とする人物の情報・設定を作るのではなく、**条件そのものを省いた簡略化**として記録します（利用者の指定は「誕生日の確認をせずに通常のコイントスのみ」）。
- 印刷の文面では、誕生日でない日はコインを投げず 30 ダメージです。指定の扱いでは毎回コインを投げるので、印刷の処理とは乱数の使い方・期待されるダメージが違います。これは簡略化による違いで、公式の処理の読み替えではありません。

発話の扱い:

- 発話の確認の入力・音声の処理・確認の操作を要求しません。

## 4. この指定で解決したとしないこと

次は、この指定とは別の問いで、**歴史的に解決したとは記録しません**（kyuura の記録は変えていない）。

- `_のピカチュウ` の名前の記名（名前の「_」の部分）による同名の判定（デッキの 4 枚の制限など）。kyuura の名前は `_のピカチュウ` のまま。
- ハマちゃんのヤドキングの表記の差: ワザの名前「こまったなあ」と、文面の中の言葉「こまったなぁ」（小さい「ぁ」）。どちらも kyuura の転記のままで、印刷をこの作業で確かめていません。
- プロモカードの大会での使用の区分（たとえば英語版の _____'s Pikachu が Unlimited でも使えなかったという WotC の記録 [docs/rules/wotc.md](rules/wotc.md)。日本語版の区分の根拠にしない）。
- 名前・進化元（ヤドン）・欠けているレベル（`jp_print.level`）・図鑑番号（PR1-072 の `pokemon.dex`）。

## 5. 変えていないもの

- `data/sidecar/rulings.json` の `engine_positions` には**加えていません**（6 章）。新しいスキーマ・取り込みの記録（`engine_imports`）も作っていません。

### 実装が完成したあとに取り込むときに要るもの

`engine_positions` に `kind: simplification` の記録（例: 既存の `ENG-V068-IMAKUNI-DODUO-SIMPLIFIED`）を加えるには、次を確かめます。今回はどれも**未確定**です。

1. エンジンの最終コミット（v0.127 の完成した版。固定したコミット）と、その版の取り込み `engine_imports`（`ENGINE-<先頭 7 桁>`）。
2. 版の文書の中の簡略化した仕様の節（`document`・`section`）。
3. 実際の登録（効果の登録表の (カード id, ワザの位置)、照合の記録）と、採用した仕様の記録。
4. 簡略化した仕様を確かめる検査の場所（エンジンのテスト）と、その結果がエンジンの報告によるものであること。
5. 指定の扱い（2 章）と、実装の扱いが同じか。違えば、ここに書いた利用者の指定とエンジンの実装を分けて書く。

取り込むときは、`cards`（3 つの id とワザの位置）・`summary`・`kyuura_handling`（「エンジンの簡略化した仕様で、公式のエラッタ・最新の説明・裁定ではない。kyuura のカードデータは印刷の文面のまま」）を書き、`engine_basis` には利用者の指定であることを書きます。そのあとで `python3 scripts/build_card_rulings.py --check` などの関連の検査を実行します。
