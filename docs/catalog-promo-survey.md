# プロモの収録範囲の調査と目録の整備（2026-10-31）

`data/cards.csv` を、対戦用のカードだけでなく、目録に収録する公式のカード類（非対戦のカード・専用ルール用のカード・ジャンボカード）も横断して検索できる一覧にし、あわせてプロモの収録範囲を、独立したプロモの一覧と当時の公式の書籍で調べた記録です。

- 作業の基点: `0dadab8`（ブランチ `claude/eloquent-lamport-5xyv5r`。main `b9e7cff` より後の公開済みの作業をすべて含む）。
- エンジン（kyuura-engine）の実装は変えていません。エンジンの登録表の写し（`data/curation/engine_registered_cards.json`）も書き換えていません。エンジンの取り込みは [引き継ぎ](engine-handover-catalog-scope.md) に書きました。
- ワザの裁定・対戦の実装の設計は、この作業の範囲の外です。

## 1. 方針と、それを表すデータ

| 方針 | データ |
|---|---|
| `data/cards.csv` を目録の横断検索の一覧にする | `data/cards.csv` の行 = `data/cards.json` の記録 + `data/product_items.json` の `non_game_items` + `data/curation/catalog_items.json` の項目。`scripts/catalog.py` が作る（`scripts/build_cardlist.py` も同じ関数で書く） |
| 目録への収録・通常対戦での使用範囲・エンジンの実装の対象を分ける | `catalog_class`（目録の分類）・`play_scope`（使用範囲。既存の欄）・`engine_scope` と `engine_scope_reason`（エンジンの対象か） |
| 非対戦の行を加えても、通常対戦の候補・エンジンの未実装の件数に入れない | 目録だけの行は `data/cards.json` に入れない。`scripts/build_engine_targets.py` は `catalog_class` が `battle` で `engine_scope` が `target` の記録だけを数え、ほかの記録は `excluded_records` に分ける |
| CSV に手で追記しない | CSV は生成物。`scripts/catalog.py --check` とテストが、CSV と生成元が同じことを確かめる |
| 総数を固定条件にしない | テストは内訳を、根拠（記録の数・移管の数・`non_game_items` の数・書籍で確かめた数）から数える |

### 生成の仕組みを選んだ理由

- 対戦のカードの記録は、今までどおり `data/cards.json` が正本です。kyuura-engine は決まったコミットの `data/cards.json` の `cards` からカードの写しを作るので、非対戦の項目を `cards` に入れると、エンジンが読む対戦のカードの集合と件数が変わります。そのため、非対戦の項目は `data/cards.json` に入れず、CSV の行にだけします。
- pcg-search の転記にある非対戦の項目は、すでに `data/product_items.json` の `non_game_items`（`scripts/non_pack.py` が転記と `data/curation/non_pack.json` から作る）にあります。同じ項目を別の場所に手入力しないよう、CSV はこれをそのまま読みます。
- pcg-search の転記にない項目（今回の入賞賞品カード・ジャンボカードなど）は、転記の元がないので、手で記録する調査の記録 `data/curation/catalog_items.json` を元データにします。`data/curation/` の手作業の決め事と同じ置き場所です。
- 記録の分類（`catalog_class`・`engine_scope`）は、既存の手作業の決め事 `data/curation/non_pack.json` に `catalog_scope` を加えて明示し、`scripts/build_cardlist.py` が生成のたびに `data/cards.json` の記録に付けます（`play_scope` と同じ方式）。指定のない記録は `battle`・`target` ですが、`play_scope` が `kangaskhan_rule` の記録に指定がなければ生成が止まります（専用ルールのカードを暗黙に対戦用にしない）。
- CSV を `data/cards.json` から分けて作り直せるようにしたのは、`data/curation/catalog_items.json` を直したときに、外部の入力（TCGdex・pokemon-tcg-data）なしで CSV を作り直せるようにするためです（`python3 scripts/catalog.py`）。`scripts/build_cardlist.py` は同じ関数を呼ぶので、どちらで作っても同じ結果です（`build_cardlist.py --check` と `catalog.py --check` の両方で確かめた）。

### CSV を読む処理の点検

kyuura の中で `data/cards.csv` を読む処理は、テスト 4 つ（`tests/test_baby_preparation_v0113.py`・`tests/test_next_engine_text_evolution.py`・`tests/test_v0122_names_text_procedures.py`・`tests/test_non_pack_engine_v068.py`。どれも「CSV の行 = `data/cards.json` の記録」を確かめていた）と、過去のコミットの CSV を読む比べ（`tests/test_engine_imports_v05_v12.py`）でした。スクリプトで CSV を読むものはありません（`scripts/build_cardlist.py` は書くだけ）。4 つのテストは、`data/cards.json` の記録の行だけを比べ、ほかの行が目録だけの行（`battle`・`target` でない）であることを確かめる形に直しました。kyuura-engine は CSV を読みません（`data/cards.json` を読む）。
