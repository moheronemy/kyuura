# 公式図鑑の種族の身長（全国図鑑 No.001〜251）

2026-10-31。「カツラのクイズ その1」（GD5-016 ほか。相手が「そのポケモンの身長」を答えるトレーナー）の実装の準備として、公式に公開されている図鑑の**種族の身長**を集める作業の記録です。データは [`data/species_heights.json`](../data/species_heights.json)、道具は [`scripts/species_heights.py`](../scripts/species_heights.py)、検査は `tests/test_species_heights.py` です。エンジンへの引き継ぎは [engine-handover-species-heights.md](engine-handover-species-heights.md) にあります。

## 1. 結果（2026-10-31）

| 状態 | 件数 | 意味 |

| 取得済み（`confirmed`） | 0 | 公式の資料から取得し、名前・姿・身長が一致した |
| 未確認（`unverified`） | **251** | 公式の資料から取得できていない（値は `null`。0cm にしていない） |

**この作業環境から公式の資料に接続できず、1 件も取得していません。** 251 件すべてが未確認（`status_reason`: `source_unreachable`）です。

- `zukan.pokemon.co.jp`（ポケモンずかん）: 外向きの接続の方針で拒否された（プロキシが CONNECT に 403。`scripts/species_heights.py fetch` の robots.txt の取得で `Tunnel connection failed: 403 Forbidden`。ウェブ取得の道具でも名前の解決に失敗）。
- `www.pokemon.co.jp`・`www.pokemon.jp`・`www.pokemon.com`（英語版の公式図鑑）も同じく 403。
- このため、**サイトの利用条件と robots.txt も読めていません**。全件の取得の前に確かめる事項として残します（3 章）。
- 記録は `data/species_heights.json` の `sources.SRC-ZUKAN-JP.access_log` にあります。
- 非公式のデータ（PokeAPI・ファンWiki・第三者の転載）で埋めていません。ウェブアーカイブ（web.archive.org）の保存版から取る経路は、接続の制限を迂回することになるので使いませんでした。保存版を公式の資料の写しとして扱うかは、利用者が決めることとして残します。
- 接続できない状況での作業は、取得・抜き出し・換算・検査の仕組みと、251 件の未確認の枠までです。

再開するには、作業環境のネットワークの設定で `zukan.pokemon.co.jp` への接続を許可してから、3 章の手順を最初の試し取りから行います。

## 2. データの位置づけ

- 集めるのは**公式図鑑の種族の身長**です。旧裏カードに印刷された身長を確かめた値ではありません。
- `data/cards.json` のカードの欄（印刷の身長などの欄はもともとない）を補完・訂正しません。この作業で `data/cards.json`・`data/cards.csv`・`data/attacks.csv`・`data/powers.csv` は変えていません（テストで基点のコミット `71d1728` と比べています）。
- 公式図鑑の値をクイズの正解として採るかは、**エンジンの仕様として別に決めます**（この収集では決めない）。カードの時期（1996〜2001年）の図鑑の値と今の公式ずかんの値が同じとは確かめていません。
- カードとは**全国図鑑番号**（`data/cards.json` の `pokemon.dex`）だけで結びます（`species_for_card`）。所有者名つきカード（「エリカのフシギダネ」など）を名前の文字列から推測して結びません（所有者名つきカードも `pokemon.dex` があればそれで結ぶ）。
- `pokemon.dex` のないポケモンのカード（2026-10-31 に 227 枚。拡張シート・ジムデッキ・クイックスターターギフト・プロモなど。`report` の `without_dex`）は結びません。この作業で図鑑番号の欠けを推測で補っていません。dex のあるポケモンのカードは 841 枚、dex はすべて 1〜251 の範囲です。

## 3. 収集の手順

出典は公式のものだけを `scripts/species_heights.py` の `SOURCES` に登録します。2026-10-31 は `SRC-ZUKAN-JP`（ポケモンずかん、株式会社ポケモン。詳細ページ `https://zukan.pokemon.co.jp/detail/{番号4桁}`）の 1 つです。

1. **利用条件の確認**: サイトの利用条件（ご利用にあたって）と robots.txt を読み、自動の取得と、抜き出した値・最小限の文字列をこのリポジトリに残してよいかを確かめます。結果を `record-access --result terms_checked --detail "..."` で記録します。許されなければ取得しません。
2. **試し取り（少数件）**: `fetch --dex 1,25,201`（10 件まで）。`fetch` は robots.txt を先に読み、許されない URL は取らず、5 秒（下限 3 秒）の間隔で 1 件ずつ取り、作業用のディレクトリ（`--cache`。リポジトリの外）に置いたものは取り直しません。
3. **形・単位・姿の確認**: `extract --dex 1,25,201 --retrieved-on <日付>` のあと、抜き出した名前・姿の番号（`sub`）・姿の名前・身長の原表記を人がページと照らします。とくに次を確かめます。
   - ページの形（4 章の想定）が実際と合うか。合わなければ抜き出しは `ParseError` で止まり（`status_reason`: `parse_failed`）、値を推測しません。そのときは抜き出しを直してから続けます。
   - 単位（m で小数 1 桁を想定）と整数 cm への換算。
   - 通常の姿の選び方（No.201 アンノーンのように姿が多い種族、姿の名前の出る種族）。
4. **全件**: `fetch --range 1-251 --full-range`（10 件を超える取得には `--full-range` が要る）→ `extract --range 1-251`。
5. **検査**: `python3 scripts/species_heights.py --check --cache <作業用のディレクトリ>` と `python3 -m unittest discover -s tests`。`report` で件数とカードとの対応を出します。

取得の失敗は観測を作らず、未確認のまま残ります（0cm にしない）。別の公式の資料を加えるときは、`SOURCES` に加え（抜き出しも）、観測を同じ種族の `observations` に足します。身長が違えば `conflict` になり、両方の観測（出典の URL・取得日・ハッシュ）が残ります。どちらかに統一しません。

## 4. 抜き出し・換算・姿の決め方

- **抜き出し**（`parse_zukan_jp`）: 詳細ページに埋めこまれた JSON（`<script id="json-data">`）の `pokemon` の `no`・`sub`・`name`・`takasa`（姿の名前は `sub_name` か `form_name`）を読むと想定しています。**この形は実際のページと照らしていません**（接続できなかった）。テストのページは架空のものです。試し取り（3 章の 2・3）で確かめるまで、この想定を事実として扱わないでください。
- **残すもの**: 画像は取りません。リポジトリには、観測ごとに抜き出し（`extract`: 番号・姿の番号・名前・姿の名前・身長の原表記）、その sha256（`extract_sha256`）、取得した応答全体の sha256 とバイト数（`response_sha256`・`response_bytes`）、URL、取得日を残します。応答そのものは残しません（再確認は、同じ URL を取り直してハッシュと抜き出しを比べる。`--check --cache`）。
- **換算**（`normalize_height_cm`）: 原表記を十進数のまま読み、m は 100 倍、cm はそのまま。整数 cm にならない値・0 以下・単位のない値はエラーにし、丸めません。
- **姿**: 当時（第1・第2世代）に対応する通常の姿だけを採ります。詳細ページの基本の姿（`sub` 0）を基本にし、姿の名前があれば `needs_review` にします。リージョンフォーム・メガシンカ・キョダイマックス・後世の姿・性別の違いの別項目は採りません。アンノーンの文字の違いは基本の姿だけを記録し、ほかの文字の姿は集めません。
- **名前の確認**: 抜き出した名前が、同じ図鑑番号の kyuura のカード名のどれかに含まれなければ `needs_review` にします（名前の出典にはしない。確認だけ）。公式の資料どうしで名前が違うときも `needs_review` です。

## 5. 検査の内容

`--check`（`check_data`）とテストは次を確かめます。

- 番号の範囲（1〜251）・重複・欠け・順番。
- 状態と値の対応（`confirmed` だけが名前・身長を持つ。未確認・食い違い・要確認は `null`）。状態が観測から決め直した結果と同じか。
- 観測の出典が登録した公式の出典か、URL が出典の詳細ページの URL か、取得日の形、原表記の換算、抜き出しとそのハッシュ・観測の値の一致。
- `--cache` があれば、保存した応答の sha256 と、応答から抜き出し直した値。
- カードデータ・目録が基点から変わっていないこと、カードとの対応が図鑑番号だけによること（テスト）。
