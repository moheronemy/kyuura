出典は公式のポケモンずかん（`SRC-ZUKAN-JP`）の 1 つだけです。ほかの公式の資料（英語版の公式図鑑など）とは比べていないので、「食い違い 0」は資料を比べた結果ではありません。

経過（`data/species_heights.json` の `sources.SRC-ZUKAN-JP.access_log`）:

1. 最初は作業環境の外向きの接続の方針で `zukan.pokemon.co.jp` に接続できず（プロキシが CONNECT に 403）、251 件を未確認の枠として作った。非公式のデータ（PokeAPI・ファンWiki・第三者の転載）や、ウェブアーカイブの保存版（接続の制限の迂回になる）では埋めなかった。
2. 利用者が `zukan.pokemon.co.jp` を許可したあと、robots.txt は 404（制限なし）。**サイトの利用条件は読めていません**: ずかんのサイトには利用条件のページがなく、フッターのリンク先の `www.pokemon.co.jp` はこの環境から接続できない。取得は 5 秒間隔で 1 件ずつ、キャッシュを使い、リポジトリには抜き出した値とハッシュだけを残した（画像は取っていない）。
3. 試し取り（No.001・025・201）で、ページの形が想定（埋めこみの JSON）と違い HTML であることが分かった。想定の抜き出しは値を作らずに止まった。実際の形に合わせて抜き出しを書き直し、姿のページ 1 つ（0026-1 アローラのすがた。データには入れない）で姿の名前の出かたを確かめた。
4. 全件（248 件を新たに取得）: 取得の失敗 0、抜き出しの失敗 0。姿の名前のあるページ・姿の番号が 0 でないページはなかった。身長の原表記はすべて「数字.数字m」（小数 1 桁の m）で、20cm〜920cm。
5. 名前の確認で No.233 だけが合わなかった: 公式の表記は全角数字の「ポリゴン２」、kyuura のカード名は「ポリゴン2」。照合だけ NFKC でそろえて比べるようにした（記録する名前は公式の表記のまま「ポリゴン２」）。

## 2. データの位置づけ

- 集めるのは**公式図鑑の種族の身長**です。旧裏カードに印刷された身長を確かめた値ではありません。
- `data/cards.json` のカードの欄（印刷の身長などの欄はもともとない）を補完・訂正しません。この作業で `data/cards.json`・`data/cards.csv`・`data/attacks.csv`・`data/powers.csv` は変えていません（テストで基点のコミット `71d1728` と比べています）。
- 公式図鑑の値をクイズの正解として採るかは、**エンジンの仕様として別に決めます**（この収集では決めない）。カードの時期（1996〜2001年）の図鑑の値と今の公式ずかんの値が同じとは確かめていません。
- カードとは**全国図鑑番号**（`data/cards.json` の `pokemon.dex`）だけで結びます（`species_for_card`）。所有者名つきカード（「エリカのフシギダネ」など）を名前の文字列から推測して結びません（所有者名つきカードも `pokemon.dex` があればそれで結ぶ）。
- `pokemon.dex` のないポケモンのカード（2026-10-31 に 227 枚。拡張シート・ジムデッキ・クイックスターターギフト・プロモなど。`report` の `without_dex`）は結びません。この作業で図鑑番号の欠けを推測で補っていません。dex のあるポケモンのカードは 841 枚、dex はすべて 1〜251 の範囲です。

## 3. 収集の手順

出典は公式のものだけを `scripts/species_heights.py` の `SOURCES` に登録します。2026-10-31 は `SRC-ZUKAN-JP`（ポケモンずかん、株式会社ポケモン。詳細ページ `https://zukan.pokemon.co.jp/detail/{番号4桁}`）の 1 つです。

1. **利用条件の確認**: サイトの利用条件（ご利用にあたって）と robots.txt を読み、自動の取得と、抜き出した値・最小限の文字列をこのリポジトリに残してよいかを確かめます。結果を `record-access --result terms_checked --detail "..."` で記録します。許されなければ取得しません。
2. **試し取り（少数件）**: `fetch --dex 1,25,201`（10 件まで）。`fetch` は robots.txt を先に読み、許されない URL は取らず、5 秒（下限 3 秒）の間隔で 1 件ずつ取り、作業用のディレクトリ（`--cache`。リポジトリの外）に置いたものは取り直しません。
3. **形・単位・姿の確認**: `extract --dex 1,25,201 --retrieved-on <日付>` のあと、抜き出した名前・姿の番号（`sub`）・姿の名前・身長の原表記を人がページと照らします。とくに次を確かめます。
   - ページの形（4 章）が実際と合うか。合わなければ抜き出しは `ParseError` で止まり（`status_reason`: `parse_failed`）、値を推測しません。そのときは抜き出しを直してから続けます。
   - 単位（m で小数 1 桁を想定）と整数 cm への換算。
   - 通常の姿の選び方（No.201 アンノーンのように姿が多い種族、姿の名前の出る種族）。
4. **全件**: `fetch --range 1-251 --full-range`（10 件を超える取得には `--full-range` が要る）→ `extract --range 1-251`。
5. **検査**: `python3 scripts/species_heights.py --check --cache <作業用のディレクトリ>` と `python3 -m unittest discover -s tests`。`report` で件数とカードとの対応を出します。

取得の失敗は観測を作らず、未確認のまま残ります（0cm にしない）。別の公式の資料を加えるときは、`SOURCES` に加え（抜き出しも）、観測を同じ種族の `observations` に足します。身長が違えば `conflict` になり、両方の観測（出典の URL・取得日・ハッシュ）が残ります。どちらかに統一しません。

## 4. 抜き出し・換算・姿の決め方

- **抜き出し**（`parse_zukan_jp`）: 2026-10-31 に確かめた詳細ページの HTML から、`og:url` の `detail/{番号4桁}[-{姿の番号}]`（姿の番号がなければ 0）、見出し `<h2 class="ttl__detail">` の `No.{番号4桁}`・`<span class="name">`・姿のページだけにある `<span class="subname">`、`<dd class="content__detail-features js-height">` を読みます。どれかが 1 つでない・見出しと URL の番号が違うときは `ParseError` で止まり、値を推測しません。サイトの形が変われば、抜き出しは止まります（作り直す前に形を確かめ直す）。テストのページは、この形だけをまねた架空のものです。
- **残すもの**: 画像は取りません。リポジトリには、観測ごとに抜き出し（`extract`: 番号・姿の番号・名前・姿の名前・身長の原表記）、その sha256（`extract_sha256`）、取得した応答全体の sha256 とバイト数（`response_sha256`・`response_bytes`）、URL、取得日を残します。応答そのものは残しません。再確認は、同じ URL を取り直して `--check --cache` で比べます。ページには取得のたびに変わる部分（読み込むファイルの版の番号など）があるので、応答のハッシュが違っても抜き出しが同じなら注記にとどめ、抜き出しが違えばエラーにします。
- **換算**（`normalize_height_cm`）: 原表記を十進数のまま読み、m は 100 倍、cm はそのまま。整数 cm にならない値・0 以下・単位のない値はエラーにし、丸めません。
- **姿**: 当時（第1・第2世代）に対応する通常の姿だけを採ります。詳細ページの基本の姿（`sub` 0）を基本にし、姿の名前があれば `needs_review` にします。リージョンフォーム・メガシンカ・キョダイマックス・後世の姿・性別の違いの別項目は採りません。アンノーンは公式ずかんに文字ごとの姿のページがなく（2026-10-31）、詳細ページの値（0.5m）を記録しました。カードの文字の違いとの対応は確かめていません。
- **名前の確認**: 抜き出した名前が、同じ図鑑番号の kyuura のカード名のどれかに（NFKC でそろえて）含まれなければ `needs_review` にします（名前の出典にはしない。確認だけ）。公式の資料どうしで名前が違うときも `needs_review` です。

## 5. 検査の内容

`--check`（`check_data`）とテストは次を確かめます。

- 番号の範囲（1〜251）・重複・欠け・順番。
- 状態と値の対応（`confirmed` だけが名前・身長を持つ。未確認・食い違い・要確認は `null`）。状態が観測から決め直した結果と同じか。
- 観測の出典が登録した公式の出典か、URL が出典の詳細ページの URL か、取得日の形、原表記の換算、抜き出しとそのハッシュ・観測の値の一致。
- `--cache` があれば、保存した応答の sha256 と、応答から抜き出し直した値。
- カードデータ・目録が基点から変わっていないこと、カードとの対応が図鑑番号だけによること（テスト）。
